# Overview

**ERP Imobiliária** for **EVE Administradora de Imóveis**: condominium administration, rentals, sales and finance. Internal tool (staff only). The reference system is "Sami ERP"; the model and rules come from its analysis. Module status and the plan live in [`roadmap/`](../roadmap/README.md).

## Stack
| Concern | Choice |
|---|---|
| Runtime | Python 3.12 (Docker/CI), Django 6.1, DRF 3.18 |
| Database | PostgreSQL 16 (`pg_trgm` required; trigram GIN indexes) |
| Auth | `accounts.User` + SimpleJWT through `AuditedJWTAuthentication` (it also tells the audit trail who acts) |
| Contract | drf-spectacular (`/api/schema/`, `/api/docs/`) → frontend client generated by orval |
| Filter/search | django-filter + `core.api.filters.QuerySearchFilter` (`?query=`) |
| Admin / static | django-unfold / WhiteNoise |
| Audit | django-auditlog: registry changes, personal values masked |
| Cache | Redis (`CACHES`); tests use local memory |
| Async | Celery + Redis (`config/celery.py`; **no tasks yet**) |
| Quality | pytest + pytest-django; mypy strict (django/drf plugins) |

`DEFAULT_AUTO_FIELD` is `BigAutoField` on purpose: it only applies to third-party tables (e.g. `token_blacklist`); every model of ours declares a UUID primary key.

## Layers (dependency direction, never reversed)
```
core  ←  accounts   (`User.company`; `core` never imports `accounts`)
core  ←  persons  ←  condominiums  ←  finance  ←  (billing, rentals, sales: future)
```
`core` holds shared infrastructure. An app imports only from apps to its left; a cycle means the code belongs in a lower layer.

## Request flow
`request → CORS → WhiteNoise → JWTAuthentication → router → ViewSet (filters, pagination) → serializer (validate) → [service] → model (rules, constraints) → PostgreSQL`. Lists answer `{count, next, previous, results}`.

## Environment variables
| Variable | Purpose |
|---|---|
| `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS` | Django basics. **`SECRET_KEY` is mandatory when `DEBUG=false`** (≥ 32 chars) |
| `JWT_SIGNING_KEY` | Ed25519 private key (PKCS#8 PEM, one line with literal `\n` allowed) that signs the JWTs with EdDSA; the public key is derived from it. **Mandatory in every environment, development included**; generate it with the command in `.env.example` (spec 020) |
| `POSTGRES_DB/USER/PASSWORD/HOST/PORT` | database. **`POSTGRES_DB` is mandatory** (no SQLite fallback) |
| `REDIS_URL` | Celery broker/result backend **and the shared cache** (the login rate limit holds across workers) |
| `SECURE_SSL_REDIRECT`, `SECURE_HSTS_SECONDS`, `ADMIN_URL` | production security (`operations.md`) |
| `INTERNAL_API_KEY` | secret shared with the Next server; lets Django trust the forwarded client address; **mandatory when `DEBUG=false`** |
| `CORS_ALLOWED_ORIGINS` | frontend origin(s) |
| `DJANGO_SUPERUSER_USERNAME/PASSWORD/EMAIL` | first admin, created by `entrypoint.sh` |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_STORAGE_BUCKET_NAME`, `AWS_S3_ENDPOINT_URL`, `AWS_S3_REGION_NAME` | the Cloudflare R2 bucket of the payment receipts (spec 018); all but the region are required, without them the receipt endpoints answer 503 |

## Vocabulary (code ⇄ business term)
Condominium, Block, Unit = Condomínio, Bloco, Unidade · Person (individual CPF / legal CNPJ) = Pessoa (física / jurídica) · UnitPerson (`owner`, `tenant`) = vínculo proprietário / locatário · AdministrationContract, BillingRules = contrato de administração, regras de cobrança · `ideal_fraction` = fração ideal (rateio) · CostCenter = centro de custo (antes "sub-conta") · EntryTemplate = modelo de lançamento (antes "histórico") · Advisor = assessor. ## Decisions
Changing one needs a feature spec.
| # | Decision → why / consequence |
|---|---|
| 1 | UUID primary keys on every model → opaque, safe to expose; ids are strings in the API |
| 2 | English code and API names, Portuguese only in UI/sample data → the generated client needs no translation; API errors are English, the frontend translates by code |
| 3 | Apps are packages (`models/`, `serializers/`, `views/`...), one entity per file → small files; re-export in `__init__.py` |
| 4 | 1:1 parts (address, contract, billing, person documents) are written through the parent serializer, which calls a service (`create_condominium`, `update_person`...) in `transaction.atomic`; child collections (unit people) have their own endpoint |
| 5 | Business rules live only in the models (validators, `clean()`, constraints); serializers run them via `ModelRulesMixin` → one source of truth for API, admin, commands and tasks |
| 6 | PostgreSQL only (trigram search) → tests and dev need Postgres |
| 7 | Documents stored digits-only → one canonical form; masks are UI-only |
| 8 | `accounts.User` is separate from `persons.Person` → login ≠ business entity; a future `Person.user` lives in `persons`; every user belongs to a `Company` |
| 9 | OpenAPI is the contract; the frontend client is generated → every API change is followed by regeneration |
| 10 | Multi-company from the start → every user sees only its company's data (`core/scoping.py`); a superuser bypasses the scope |
| 11 | Migration history reset to one `0001` per app before production → see `operations.md` |
| 12 | Spec-first workflow; ask on any gap → `features/` is mandatory for features |
| 13 | Celery/Redis provisioned but unused → jobs (boleto, mail) are coming; workers disabled on the free plan |
| 14 | Dashboard adjustments are computed in Python over the active contracts → fine for tens of condominiums; move to SQL (spec) when active contracts pass ~1,000 or the dashboard passes ~500 ms |
| 15 | A use case that orchestrates several models or a transaction is a **service** (`services/<use_case>.py`, one file per use case); the rules stay in the models and the service never raises its own `ValidationError` |
| 16 | Production runs on one VPS with Docker Compose behind an existing Caddy; payment receipts live in a private Cloudflare R2 bucket and are moved by signed URLs (the file never crosses Next or Django) → no managed platform to pay, one proxy owns ports 80/443; the web stack stays stateless apart from Postgres (`operations.md`, spec 018) |
