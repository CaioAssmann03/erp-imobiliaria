# Overview

**ERP Imobiliária** for **EVE Administradora de Imóveis**: condominium administration, rentals, sales and finance. Internal tool (staff only; admins log in).
The reference system is "Sami ERP"; the model and rules come from its analysis. Module status and the plan live in [`roadmap/`](../roadmap/README.md).

## Stack
| Concern | Choice |
|---|---|
| Runtime | Python 3.12 (Docker/CI), Django 6.1, DRF 3.18 |
| Database | PostgreSQL 16 (`pg_trgm` required; trigram GIN indexes) |
| Auth | `accounts.User` + SimpleJWT (access 30 min, refresh 7 days, rotating) through `AuditedJWTAuthentication`, which also tells the audit trail who acts |
| Contract | drf-spectacular (`/api/schema/`, `/api/docs/`) → frontend client generated by orval |
| Filter/search | django-filter + `core.filters.QuerySearchFilter` (`?query=`) |
| Admin / static | django-unfold / WhiteNoise |
| Audit | django-auditlog 3.4.1 (spec 005): registry changes, personal values masked |
| Cache | Redis (`CACHES`, Django `RedisCache`); tests use local memory |
| Async | Celery + Redis (`config/celery.py`; **no tasks yet**) |
| Quality | pytest + pytest-django; mypy strict (+ django/drf plugins), blocking in CI |

## Layers (dependency direction, never reversed)
```
core  ←  accounts   (`User.company`; `core` never imports `accounts`)
core  ←  persons  ←  condominiums  ←  finance  ←  (billing, rentals, sales: future)
```
`core` holds shared infrastructure (Company, validators, pagination, search filter, dashboard, search). An app imports only from apps to its left;
a cycle means the code belongs in a lower layer.

## Request flow
`request → CORS → WhiteNoise → JWTAuthentication → router → ViewSet (filters, pagination) → serializer (validate, nested write) → model (rules, constraints) → PostgreSQL`.
Lists answer `{count, next, previous, results}`.

## Settings (`config/settings.py`, one env-driven file)
`AUTH_USER_MODEL="accounts.User"`, `LANGUAGE_CODE="pt-br"`, `TIME_ZONE="America/Sao_Paulo"`, DRF defaults (`JWTAuthentication`, `IsAuthenticated`,
`StandardPagination`, spectacular). `DEFAULT_AUTO_FIELD` is BigAutoField on purpose: Django accepts no UUID value there, and it only applies to third-party tables (e.g. `token_blacklist`); every model of ours declares a UUID primary key.

## Environment variables
| Variable | Purpose |
|---|---|
| `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS` | Django basics. **`SECRET_KEY` is mandatory when `DEBUG=false`** (≥ 32 chars: it signs the JWTs); cookies are `Secure` when `DEBUG=false` |
| `POSTGRES_DB/USER/PASSWORD/HOST/PORT` | database. **`POSTGRES_DB` is mandatory** (`ImproperlyConfigured` otherwise; no SQLite fallback) |
| `REDIS_URL` | Celery broker/result backend **and the shared cache** (`CACHES`: the login rate limit holds across workers) |
| `SECURE_SSL_REDIRECT`, `SECURE_HSTS_SECONDS`, `ADMIN_URL` | production security (see `operations.md`): defaults on / 3600 s / `admin/` |
| `INTERNAL_API_KEY` | secret shared with the Next server (same value on both sides); lets Django trust the forwarded client address for the login rate limit; **mandatory when `DEBUG=false`** |
| `CORS_ALLOWED_ORIGINS` | frontend origin(s) |
| `DJANGO_SUPERUSER_USERNAME/PASSWORD/EMAIL` | first admin, created by `entrypoint.sh` |
Planned (placeholders only): `SANTANDER_*` (bank API), `RESEND_API_KEY` (e-mail).

## Decisions
Changing one needs a feature spec.
| # | Decision → why / consequence |
|---|---|
| 1 | UUID primary keys on every model → opaque, safe to expose; ids are strings in the API |
| 2 | English code and API names, Portuguese only in UI/sample data → the generated client needs no translation; API errors are English, the frontend translates |
| 3 | Apps are packages (`models/`, `serializers/`, `views/`), one entity per file → small files; re-export in `__init__.py` |
| 4 | 1:1 parts (address, contract, billing, person documents) are written through the parent serializer in `transaction.atomic`; child collections (unit people) have their own endpoint |
| 5 | Business rules live only in the models (validators, `clean()`, constraints); serializers run them via `ModelRulesMixin` → one source of truth for API, admin, commands and tasks; new write paths call `full_clean()` |
| 6 | PostgreSQL only (trigram search) → tests and dev need Postgres |
| 7 | Documents stored digits-only → one canonical form; masks are UI-only |
| 8 | `accounts.User` is separate from `persons.Person` → login ≠ business entity; a future `Person.user` 1:1 lives in `persons`; every user belongs to a `Company` (`accounts` depends on `core`) |
| 9 | OpenAPI is the contract; the frontend client is generated → every API change is followed by regeneration |
| 10 | `Company` from the start (multi-company) → every user belongs to one company and sees only its data (`core/scoping.py`, spec 004); a superuser bypasses the scope |
| 11 | Migration history reset to one `0001` per app before production → see the warning in `architecture/operations.md` |
| 12 | Spec-first workflow; ask on any gap → `features/` is mandatory for features |
| 13 | Celery/Redis provisioned but unused → jobs (boleto, mail) are coming; workers disabled on the free plan |
| 14 | Dashboard adjustments are computed in Python over the active contracts → fine for tens of condominiums; move to SQL (spec) when active contracts pass ~1,000 or the dashboard passes ~500 ms |
