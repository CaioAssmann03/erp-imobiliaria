# Overview

| Concern | Choice |
|---|---|
| Language/runtime | Python 3.12 (Docker/CI), Django 6.1, DRF 3.18 |
| Database | PostgreSQL 16 (`pg_trgm` extension required; trigram GIN indexes) |
| Auth | `accounts.User` + SimpleJWT (access 30 min, refresh 7 days, rotating) |
| API docs/contract | drf-spectacular (`/api/schema/`, `/api/docs/`) → frontend client generated by orval |
| Filtering/search | django-filter + `core.filters.QuerySearchFilter` (`?query=`) |
| Admin | django-unfold |
| Async | Celery + Redis (configured in `config/celery.py`; **no tasks yet**) |
| Static | WhiteNoise |
| Quality | pytest + pytest-django, mypy (strict + django/drf plugins; not enforced in CI) |

## Layers (dependency direction, never reversed)

```
accounts            (independent)
core  ←  persons  ←  condominiums  ←  financeiro  ←  (cobranca, locacoes, vendas: future)
```
`core` holds shared infrastructure (Company, validators, pagination, search filter, dashboard, search). An app may import from apps to its
left only. A cycle means the code belongs in a lower layer.

## Request flow
`request → CORS → WhiteNoise → JWTAuthentication → router (app urls) → ViewSet (filter backends, pagination) → serializer (validate, nested
create/update) → model (constraints) → PostgreSQL`. Responses are paginated `{count, next, previous, results}`.

## `config/`
`settings.py` (single file, env-driven), `urls.py` (admin, auth, schema/docs, includes each app's `urls.py`), `celery.py`, `wsgi.py`/`asgi.py`.
Key settings: `AUTH_USER_MODEL="accounts.User"`, `LANGUAGE_CODE="pt-br"`, `TIME_ZONE="America/Sao_Paulo"`, DRF defaults
(`JWTAuthentication`, `IsAuthenticated`, `StandardPagination`, spectacular schema). `DEFAULT_AUTO_FIELD` is BigAutoField but every model
declares a UUID primary key explicitly.

## Environment variables
| Variable | Purpose |
|---|---|
| `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS` | Django basics; **`SECRET_KEY` is mandatory when `DEBUG=false`** (startup fails otherwise); session/CSRF cookies are `Secure` when `DEBUG=false` |
| `POSTGRES_DB/USER/PASSWORD/HOST/PORT` | database. **`POSTGRES_DB` is mandatory**: settings raise `ImproperlyConfigured` without it (the project runs on PostgreSQL only; there is no SQLite fallback) |
| `REDIS_URL` | Celery broker/result backend |
| `CORS_ALLOWED_ORIGINS` | frontend origin(s) |
| `DJANGO_SUPERUSER_USERNAME/PASSWORD/EMAIL` | first admin created by `entrypoint.sh` |

## Running and deploying
- Local: `docker compose up -d`; `docker compose exec backend python manage.py migrate` (and `createsuperuser`, optional `seed_demo`).
  Backend runs `runserver`; `celery_worker` and `celery_beat` services exist.
- Production (Render, Blueprint `render.yaml`): Docker image; `entrypoint.sh` runs `migrate`, `collectstatic`, optional `createsuperuser`, then gunicorn.
- CI (`.github/workflows/ci.yml`): Postgres + Redis services; `makemigrations --check`, `migrate`, `check`, tests (see known-gaps.md about the test command).
