# App `core`

Shared infrastructure plus the read-only dashboard and global search (which read the domain apps). Anything two or more apps need belongs here. `accounts` depends on `core`, never the reverse.

## What lives here
| Piece | Where | Note |
|---|---|---|
| `Company`, base models, generic querysets | `models/`, `models/querysets/` | `UUIDModel` (id) and `BaseModel` (id + timestamps), abstract: every model inherits one. `ModelRules` / `@rule` (`models/rules.py`): the base of the `models/rules/` classes. `models/querysets/counts_by_type.py`: `CountsByTypeQuerySet` (`totals()`, `count_by_type()`) for models with `active` and `type` fields; `Condominium` and `Unit` extend it |
| `Address` | `models/address.py`, `serializers/address_serializers.py` | a postal address any entity can point at (spec 043; it was `condominiums.Address`): table `address`, its own required `company` (`PROTECT`, the scope), `zip_code`, `street`, `number`, `complement`, `district`, `city`, `state`. It has no endpoint of its own: an owner nests `AddressSerializer` in its payload and creates the row with its company (`Condominium.address` is the first owner). It imports nothing from the apps that use it |
| Sequential ID | `models/sequential_code.py` | `sequential_code_field(sequence)` and `SequentialCodeMixin` (spec 019): a `BigIntegerField` the database fills from its own sequence on insert; `validate_unique` skips it so `full_clean()` draws no number. Used by `Person` and `Condominium` |
| Company scoping | `infrastructure/scoping.py`, `infrastructure/api/permissions.py` | `scope_to_company` is the one place that decides (a superuser bypasses); the viewset, related-field and admin mixins; `request_company`. Every model declares `company_lookup`; guard tests fail for a model or viewset without it |
| Model rules in serializers | `serializers/model_rules.py` | `ModelRulesMixin`: input is validated by the model's `full_clean()` and returned as a 400; relation fields are company-scoped |
| Error contract | `infrastructure/api/exception_handler.py`, `infrastructure/errors/` (with `registry.py`), `infrastructure/api/schema.py` | every error becomes `{errors: [{field, code, message}]}`; `RuleError` (`errors/base.py`) is the base of every app's `errors/<entity>.py`; the registry collects them for the OpenAPI `ErrorCodeEnum` |
| Audit trail | `infrastructure/audit.py`, `admin.py` | `register_audited`, `AUDIT_EXEMPT`, masked personal values; each app registers in its own `audit.py`; the log admin is superuser-only and read-only |
| Object storage | `infrastructure/storage/object_storage.py`, `infrastructure/errors/object_storage.py` | the only module that imports `boto3`: `get_object_storage()` builds the R2 client from the `AWS_*` settings (any missing one raises the coded 503 `ObjectStorageUnavailable`); signed upload and download URLs, `object_size`, `delete_object`. Tests replace `get_object_storage` with a fake |
| Validators, pagination, search | `infrastructure/validators/`, `infrastructure/api/pagination.py`, `infrastructure/api/filters.py` | `validate_cpf` / `cnpj` / `percentage` / `first_day_of_month`; `?page` + `?limit` (default 20, max 100); `?query=`; a view with `search_code_field = "code"` also matches a term of only digits against the ID and lists that record first (`code_from_term` in `infrastructure/search/term.py` decides what is an ID) |
| Migrations | `migrations/` | `0001` runs `TrigramExtension()` first (`persons.0001` depends on it); `0002` seeds the single company record the app starts with; `0003` to `0006` bring `Address` from `condominiums` (spec 043) |

## Archiving (spec 062)
`models/soft_delete.py`: `SoftDeleteMixin` (a `deleted_at` column, `delete()` archives, `restore()`, `hard_delete()`, `is_archived`), `SoftDeleteQuerySet` (a queryset `delete()` archives each row, so it cannot bypass the model's archive rules; `hard_delete()` is the one way to really delete, used by the seed cleanup and tests) and `SoftDeleteManager` (hides archived rows). A model uses `objects = SoftDeleteManager.from_queryset(XQuerySet)()` and `all_objects = XQuerySet.as_manager()`, and overrides `validate_archivable()` with its `XArchiveRules` (a `ModelRules` class: the first violated rule is the coded 400). Django resolves a foreign key with the base manager (a unit still reaches its archived condominium) and a reverse relation with the default manager (`condominium.units` hides archived units). `infrastructure/soft_delete_admin.py`: `SoftDeleteAdminMixin` (the Admin lists live and deleted records through the `deleted` filter, restores them and turns a refused deletion into a message). Archivable: `Condominium`, `Block`, `Unit`, `Person`, `Supplier`, `CostCenter`.

## Admin organization and the Arquivados page (spec 063)
`config/settings.py` (`UNFOLD`): the sidebar is written by hand, in Portuguese, grouped as Cadastros, Financeiro, Cobrança, Gateway e boletos (técnico) and Sistema (every group but Cadastros collapses and opens by itself on its own pages); the colors are the site's (`COLORS`: the orange `#f05a28` as primary and the warm neutrals of `globals.css` as base, light and dark) with the shapes in `static/admin/metri.css`; every Admin inherits `MetriModelAdmin` (`infrastructure/admin_base.py`: compact forms, filters in a side sheet, unsaved-changes warning, Portuguese `FIELD_LABELS` for form fields and list headers with an admin's own `field_labels`, `hide_on_add` for database-filled fields such as the sequential code); the main forms are split in tabs (`fieldsets` with the `tab` class, inlines with `tab = True`); the Admin home (`config/templates/admin/index.html`, `infrastructure/admin_home.py`) is a card per group with the number of deleted records on Arquivados; every registered model must have an item (`tests/test_admin_sidebar.py` fails when a new Admin is not listed). `<ADMIN_URL>archived/` (`infrastructure/archived_admin.py`, template `templates/admin/archived_records.html`, URL name `admin_archived`) is the **Arquivados** page: a tab per archivable model (every Admin that uses `SoftDeleteAdminMixin`, so a new one appears alone) with the deleted records of the user's company, a search through the Admin's `search_fields`, and **Restaurar** per row; a refusal (a name taken meanwhile) shows as a message. A model's Admin can add buttons with `archived_actions` (`ArchivedAction`): the person's **Anonimizar** (superuser only, spec 062). It needs the change permission of the model.

## Endpoints
- `/api/companies/`: staff list, read and edit **only their own company**; create and delete are superuser-only (403).
- `/api/dashboard/` (`DashboardView`): read-only summary of what needs action. It holds **no business rule**: it calls the model and queryset methods shared with the `?pending=` filters. A `DashboardContext` (reference date, adjustments, leases, active units) is built once and small functions read it. The code is the package `views/dashboard/`, organized **by card**: `dashboard_views.py` (only `DashboardView`), `serializers.py` (`DashboardSerializer`, which composes the cards'), the shared `scoped_data.py` and `context.py`, and one sub-package per card (`registrations`, `responsibles`, `adjustments`, `fixed_revenue`, `leases`, `pending`, `accounts_payable`) holding `data.py` (what the card computes) and `serializers.py` (its part of the response). A card never imports the view; `context.py` imports the `adjustments` and `leases` data, so those two never import `context`. This is the one place in the app that groups by feature instead of by layer (`serializers/` has no dashboard file). The response keys are documented by the cards' serializers; renaming one is a contract change (the client must be regenerated).
- `/api/search/?q=` (`SearchView`): valid with 3+ characters (2+ if numeric); documents match on digits; 5 results per type, "starts with" first. It searches **people** (name, CPF/CNPJ, ID), **condominiums** (name, CNPJ, ID), **units** (number), **blocks** and **cost centers** (name), **accounts payable** (description, document number, supplier), **billing plans** (name) and **billing documents** (payer name, unit number; the latest month first); the last five match text only, so a single digit (an ID lookup) returns nothing for them. Each type's matching lives in a `search(query)` method of its own queryset (what is searchable is the entity's knowledge), and `views/search/<type>.py` only applies the company scope and the 5-row cut; all company-scoped; the response always carries every group. A term of only digits (1 to 18) is also an ID lookup: the record with that `code` comes first in the people and condominiums groups (a unit has no ID: it is found by its number), and a single digit searches only the ID, so it returns no unit. The search is not limited to a module: it finds people of every module (spec 046 dropped the `?module=` filter, which the header search always sent as `condominiums`). Every person and condominium item carries its `code`. The code is the package `views/search/` (`search_views.py`, only `SearchView`, plus one thin module per type) and the package `apps/core/infrastructure/search/`, which the querysets import: `term.py` (classification and minimum lengths), `ranking.py` (relevance, `LIMIT_PER_TYPE`) and `text_match.py` (the name conditions).

## Definitions the dashboard uses
Next adjustment = `adjustment_base_date + adjustment_period_months`. A link is **current** when `end_date` is empty or ≥ today. Apportionment is inconsistent when the active units' fractions in the main criterion, or in another criterion in use (a sum above 0), do not sum 1 (more than 0.0001 away: `CondominiumApportionmentCriterion.is_inconsistent`). Leases ending soon: tenant links ending from −30 to +60 days. Accounts payable: only `open` accounts (company expenses included), by due window.

## Layout
`infrastructure/` holds the technical plumbing every app uses, apart from the pieces of the product: `api/` (the DRF and HTTP plumbing: `exception_handler`, `pagination`, `permissions`, `throttling`, `schema`, `filters`, `middleware`), `errors/` (the error base, the shared validator and storage errors and `registry.py`, which also reads `core`'s own errors from here), `validators/`, `fields/` (`EncryptedTextField`: text encrypted at rest with Fernet, key `GATEWAY_CREDENTIALS_KEY`), `storage/`, `search/` (term, ranking and text matching), `scoping.py`, `audit.py` and `dates.py`. What stays at the root of `core` is the product: `models/` (Company and the base models), `serializers/`, `views/` (company, dashboard, global search), `admin.py`, `urls.py` and `testing.py`. Settings refer to `apps.core.infrastructure.api.*` by dotted string.

## Tests
`tests/` keeps what protects a business rule, company isolation, the audit trail or the error contract (configuration and framework behavior are not tested here), grouped by area: `dashboard/`, `search/`, `scoping/`, `company/`, `errors/` (error codes, contract, model rules), `infrastructure/` (audit, health, throttling, object storage, dates, the 038 data migrations), `architecture/` (layout guards) and `validators/`. The helpers `base.py` and `scoping_data.py` stay at the top; a test imports them with `from ..base import ...`. A test that locates files from `__file__` counts the extra folder level.
