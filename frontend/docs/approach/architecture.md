# Architecture and approach (A — Approach)

Next.js App Router + TypeScript + Tailwind v4 + TanStack Query. The backend (Django/DRF) is reached only
through the API, using a client generated by orval.

## Stack

| Concern | Choice |
|---|---|
| Framework | Next.js App Router, React 19 (a client-side app: the server only delivers static shells) |
| Data + cache | TanStack Query v5, fetched in the browser |
| API client | orval-generated hooks over axios |
| Forms | react-hook-form + Zod |
| UI | Tailwind v4 tokens, shadcn/ui on Base UI, lucide, sonner, recharts |
| Auth | JWT in cookies, refreshed by `proxy.ts` |
| Package manager | pnpm, pinned by `packageManager` in `package.json`; lockfile `pnpm-lock.yaml` (CI and Docker install with `--frozen-lockfile`) |

## Key decisions

| Decision | Why | Consequence |
|---|---|---|
| ERP pages render on the client | the ERP is almost entirely interactive (lists, filters, forms); the server only draws a shell (`metadata`, `PageHeader`) | a page makes no API call on the server; the table or form fetches with the generated hook and shows a skeleton while it loads |
| No server-side data, including the home | the login has no data and the home is as interactive as the rest | a page never prefetches; most routes are prerendered static (`○` in `next build`) and only `[id]` routes are rendered on demand, with no API call |
| Server owns filtering, pagination, rules | single source of truth | the client never downloads everything to filter |
| Generated API client | types and hooks never drift from the backend | never edit `lib/api/generated/`; regenerate |
| Form fields named like API fields | server errors land on the right field | no mapping layer |
| Tokens in cookies, refreshed in `proxy.ts` | server components need a valid token and cannot write cookies | see safeguards/auth-and-tokens.md |
| Routes and code in English, UI in Portuguese | match the backend; users read pt-BR | see norms/language-and-naming.md |

## Data flow: a list page

1. `page.tsx` (server, no data): `metadata`, `PageHeader` and `<XxxTable/>`; a table that reads the URL (`useSearchParams`) sits inside `<Suspense fallback={<ListFallback/>}>`.
2. `XxxTable` (client): the generated hook → skeleton, then the data; search/filter/page refetch. Filters present in the URL (`?condominium=`) are read with `useSearchParams` as the initial filter.
3. Mutation `onSuccess`: invalidate the list, the record and the dashboard.

Edit pages: the page awaits `params` and passes the `id`; the form loads the record with `use…Retrieve(id)` (`FormSkeleton` while loading), calls `throwIfNotFound(error)` (a 404 becomes `not-found.tsx`) and `reset(xxxToForm(record))`. A read-only detail page (billing document, run) uses a small client `…Detail` component that fetches and renders the view.

## Rendering and routing

- `page.tsx`/`layout.tsx` are server components, but a page does not fetch: `params` is a Promise (`await`), and `searchParams` is read on the client with `useSearchParams` (no page reads it on the server, so list routes stay static).
- The rail expands (icons with names) and collapses (icons only, the default) when the logo is clicked; the choice is kept in `localStorage` (`use-rail-expanded.ts`), never in a cookie or an `<html>` attribute, so the server HTML stays the same for everyone.
- The root layout and `AppShell` read no cookie: the theme is applied to `<html>` by an inline script before the first paint (norms/design-system.md), so the HTML is the same for every user and can be prerendered. `[id]` routes stay dynamic only because Next renders unknown params on demand.
- `proxy.ts` (before every request): no token → `/login?next=`; token expiring (< 30 s) → refresh and forward new
  cookies to the server render and the browser; refresh failure → `/login`.
- Every page exports `metadata` (Portuguese title; root template `"%s · METRI"`).
- `Suspense` around a client component that reads `useSearchParams`; `loading.tsx` while a page change renders; recoverable failures: `error.tsx`; missing record: `throwIfNotFound` (`lib/query/not-found.ts`) from the client.
- This Next.js version has breaking changes: check `node_modules/next/dist/docs/` for anything not covered here.
