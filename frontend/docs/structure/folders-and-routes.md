# Folders and routes (S — Structure)

```
app/
  layout.tsx, providers.tsx, globals.css    root: fonts, theme attrs, QueryClientProvider, Toaster
  login/                                     public (page.tsx + _components/)
  (marketing)/                               public product pages: `/` landing, features, how-it-works (forced light mode + orange accent, Lenis smooth scroll, `motion` animations; the "Agendar demonstração" target is `CONTACT_HREF` in `_components/content.ts`, still a placeholder; the hero is a centered serif title over an orange skyline drawn as horizontal scanlines on a canvas, `_components/hero/skyline-scene.ts`; public-page type, colors and buttons follow norms/marketing.md)
  (dashboard)/                               authenticated (route group, not in the URL)
    layout.tsx, dashboard/page.tsx           AppShell, dashboard home (`_components/home/DashboardHome.tsx` fetches)
    _components/shell/                       rail (expands/collapses on logo click) + module menu, mobile menu, global search (full bar on `/dashboard`; elsewhere on desktop a magnifier + shortcut button at the bottom of the rail (`SearchRailButton`, just above settings and logout; on a phone the header icon); click or shortcut opens the centered panel), settings
    _components/home/                        row 1 the money in and out, three equal cards: `billing-month` (R$ issued/received/open from `billing-documents/summary`), `delinquency` (overdue boletos) and accounts payable (the overdue value and three windows); row 2 the issued × received area chart (`BillingSummaryChart`, 6 months) beside pending; row 3 the upcoming adjustments list. Each card is a widget with a focus view (`widgets/focus/`); adjustments, responsibles and fixed revenue have no card and only open in the focus view and the search
    condominiums/  persons/                  one folder per resource, each with _components/
components/   ui/ (shadcn) · data-list/ (lists, `Pagination`) · form/ (+ `fields/`) · dates/ · filters/ (scope, filter menus, search combobox) · persons/ (search select, quick-create) · layout/ (`PageHeader`, `BackLink`, `SectionIndex`) · errors/ · brand/ · a few loose single-purpose buttons
hooks/        shared hooks (debounce, list params, CEP lookup)
lib/          one folder per concern, no loose files except `utils.ts` (the shadcn alias):
                api/ (generated: never edit · mutator · api-client · api-path · pagination)  query/  schemas/ (Zod, per resource)
                auth/ (cookies, jwt, safe-redirect)  errors/ (messages, details, screens, form-errors, toast)  theme/ (appearance, mode, zoom, `ui.ts` class strings)
                format/ (format, masks, validators, calendar)  navigation/ (module-menu, search-index, back-target, platform)
                billing/ condominiums/ finance/ persons/ reports/ (per domain: `*-workspace` URL + frame state, payload builders, rules)
proxy.ts      route protection + token refresh
docs/         REASONS documentation
```

`_`-prefixed folders are private (not routes).

`app/(dashboard)/` also holds `loading.tsx` (skeleton on a page change), `error.tsx` (an unexpected error, with retry) and `not-found.tsx`; `error.tsx`, `not-found.tsx`, the root `app/not-found.tsx` and `app/global-error.tsx` (a failure in the root layout) render the shared `components/errors/ErrorScreen.tsx` (the code drawn as orange scanlines that run in top to bottom, content centered, hovering the code darkens the scanlines under the pointer, plain square `ErrorActionButton`s). Copy, hint and actions per code live in `lib/errors/error-screens.ts` (18 codes: 400 401 402 403 404 405 408 409 410 413 415 422 423 429 500 501 502 503 504; any other 400–599 gets a generic screen of its range; 429 and 503 hold *Tentar de novo* behind a countdown, `retryAfter`; 5xx screens show a reference, the Next `digest`). The screens appear only for real errors: a detail page that fails to load its record calls `throwIfPageError` (`lib/query/page-error.ts`) and `error.tsx` picks the screen from the response status (`errorScreenCodeOf`: 403, 410, 429, 5xx, 408 on timeout, 502 with no response, 404 goes to `not-found.tsx`); a 401 still goes to the login (`lib/api/api-client.ts`) and errors of a save (409, 413, 415, 422, 423...) stay toasts and field errors so the form is not lost. Tested by `tests/error-screens.test.mjs`.

## Where new code goes

| It is... | Goes in |
|---|---|
| component of one route | `app/<route>/_components/` |
| component of two or more routes | `components/` |
| dashboard layout piece | `app/(dashboard)/_components/shell/` |
| hook of one route / shared hook | beside its components / `hooks/` |
| Zod schema | `lib/schemas/` |
| mask, validator, formatter | `lib/format/` |
| URL / frame-state helpers, payload builders, rules of one domain | `lib/<domain>/` (`billing`, `condominiums`, `finance`, `persons`, `reports`) |
| API call | never by hand: generated hook |

A route component that gains a second user moves to `components/`.
